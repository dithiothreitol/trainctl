# Poprawki po audycie 0.2.0

Wdrożenie obejmuje A01–A11 oraz obsługę ograniczenia A12 z
[raportu](2026-09-05-code-audit.md). Regresje:
[`audit-fixes.test.ts`](../../packages/cli/src/audit-fixes.test.ts).

| Ustalenie | Zmienione zachowanie |
|---|---|
| A01 | Jednostki są rozliczane do budżetu. Mała baza nie wymusza dwóch akcentów. Lint ujawnia odstępstwa kilometrażu i udziału easy. |
| A02 | Rekalibracja aktualizuje tempa istniejących jednostek. Zmiana objętości używa przyszłego tygodnia jako odniesienia i zapisuje bazę w `loadState`. |
| A03 | Osobny dystans zawodów; zgodność treningowa wyklucza starty po obu stronach. Brak czasu zawodów jest jawnie nieznany. |
| A04 | Zbiegi są w dystansie i czasie. Eksport zachowuje końcówki biegu zmiennego i progresji; estymator liczy końcową przerwę. |
| A05 | Propozycja wygasa przy zmianie lokalnej daty. Historyczny wybór tygodnia nie odblokowuje jego edycji. |
| A06 | Konflikt zawodów zatrzymuje generowanie i wskazuje datę. Odległy start nie wyłącza sprawdzianów na cały sezon. |
| A07 | Preferowany dzień długiego jest używany już podczas generowania. |
| A08 | Blokada całego dnia usuwa siłę i raportuje kompromis. |
| A09 | `shift` chroni starty kontrolne, wykonane sesje, przypięcia i budżety oraz sprawdza wynik przez pełny lint. |
| A10 | Walidacja dziennika i konfiguracji odrzuca nieprawidłowe liczby, czasy i daty. |
| A11 | `--test-time` / MCP `testTime` oznacza czas samego pomiaru. Bez niego program prosi o wynik. |
| A12 | Częstotliwość jest przekazywana do taperu. Niewykonalna liczba sesji przy dostępności i odpoczynku przed startem jest raportowana. |

Weryfikacja: 606 testów w 44 plikach oraz kontrola typów przeszły. Dodano
21 przypadków, w tym redukcja → zastosowanie → rekalibracja, upływ czasu,
małe bazy kilometrażowe i osobny wynik sprawdzianu. Historyczne testy operacji
zapisu używają kontrolowanego zegara.
Przeszły również build pięciu pakietów i instalacja z tarballi w czystym
katalogu: generowanie i sprawdzenie planu, mobilny eksport zawodów, pomoc
CLI z `--test-time` oraz inicjalizacja MCP. Ostrzeżenia lintu są widoczne już
przy `plan`, nie dopiero po osobnym wywołaniu `check`.

Dotychczasowe plany nie są automatycznie przeliczane. Świadoma regeneracja może
zmienić liczbę i objętość jednostek. Stare propozycje należy przygotować ponownie.
Niewykonalny budżet lub częstotliwość pozostają jawnym odstępstwem do decyzji.

Nie dodano całej listy przyszłych funkcji: krótszych wariantów akcentów, nowego
programu powrotnego, planu bez zawodów ani nowego repertuaru treningowego.
Wymagają odrębnych reguł treningowych; nie są częścią tych poprawek.

W kolejnym etapie, włączonym do wydania 0.3.0, dodano krótsze warianty,
wyjaśnienia jednostek w kontekście i `review --prepare`. Ich zakres opisuje
[przewodnik](../REVIEWED-ADAPTATION.md); pełny zestaw liczy teraz 641 testów.

`2026-09-05-reproduce.mjs` pozostaje historycznym dowodem dla commita `70b40c4`.
Potwierdza stare błędne zachowanie, więc naprawiony kod weryfikują nowe testy,
a nie ten historyczny skrypt.
